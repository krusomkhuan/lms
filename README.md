# Vocational Teacher — ครูสมควรออนไลน์

ระบบจัดการเรียนการสอนออนไลน์ (LMS) สำหรับครูอาชีวศึกษา
PHP 8 + MySQL/MariaDB (mysqli, prepared statements) + Bootstrap 5

**เวอร์ชันปัจจุบัน: 1.11.0** — ดูรายละเอียดการเปลี่ยนแปลงใน [CHANGELOG.md](CHANGELOG.md)
คู่มือการใช้งานสำหรับผู้เรียน ครู และผู้ดูแลระบบ อยู่ในเว็บที่ `manual.php` (เมนู "คู่มือการใช้งาน")
เลขเวอร์ชันกำหนดที่ `includes/version.php` (แสดงที่ท้ายหน้าบ้าน แถบเมนูหลังบ้าน และหน้าติดตั้ง)

## การติดตั้ง (XAMPP)

1. วางโฟลเดอร์ไว้ที่ `C:\xampp\htdocs\lms` แล้วเปิด Apache + MySQL ใน XAMPP Control Panel
2. คัดลอก `config/config.example.php` เป็น `config/config.php` แล้วตั้งค่าฐานข้อมูลให้ตรงกับเซิร์ฟเวอร์ (ห้ามนำไฟล์ค่าตั้งค่าจริงขึ้น Git)
   URL ของเว็บตรวจหาอัตโนมัติ ย้ายโฟลเดอร์ได้เลย หรือกำหนดเองที่ **หลังบ้าน → ตั้งค่าระบบ → URL เว็บไซต์**

> **ตั้ง URL ผิดจนเข้าเว็บไม่ได้?** เปิดบรรทัด `define('BASE_URL', 'http://localhost/lms');` ใน `config/config.php`
> (ใส่ URL ที่ถูกต้อง) แล้วเข้าไปแก้ในหลังบ้าน จากนั้นปิดบรรทัดนั้นอีกครั้ง
> หรือรัน SQL: `UPDATE settings SET value = '' WHERE name = 'site_url';`
3. เปิด <http://localhost/lms/install.php> ตั้งชื่อผู้ใช้/รหัสผ่านผู้ดูแลระบบ แล้วกด "ติดตั้งระบบ"
   (ระบบสร้างฐานข้อมูลและตารางจาก `database/lms.sql` ให้อัตโนมัติ)
4. ติดตั้งเสร็จจะมีไฟล์ `config/installed.lock` — ถ้าต้องการติดตั้งใหม่ให้ลบไฟล์นี้ (ข้อมูลเดิมจะถูกล้าง)

## สื่อหลายรายการในบทเรียน

หน้า **เพิ่มบทเรียน** กดปุ่มชนิดสื่อเพื่อเพิ่มรายการได้ทันที เช่น เพิ่มข้อความ YouTube PDF รูปภาพ และเสียงในบทที่ 1 แต่ละรายการมีชื่อ เนื้อหา ลิงก์/ไฟล์อัปโหลดของตนเอง กดชนิดเดียวกันซ้ำได้ ลบรายการที่ยังไม่บันทึกได้ แล้วกดบันทึกบทเรียนครั้งเดียว ระบบบันทึกบทเรียนและสื่อทั้งหมดพร้อมกัน หากกรอกผิดจะคงค่าข้อความไว้ แต่ต้องเลือกไฟล์อัปโหลดใหม่

ในหน้าเพิ่ม/แก้ไขสื่อ กด **เพิ่มลิงก์อีกบรรทัด** เพื่อเพิ่มช่องชนิดสื่อ ชื่อ และ URL หลายบรรทัด แล้วบันทึกครั้งเดียว แต่ละบรรทัดเป็นสื่อแยกรายการ สามารถลบบรรทัดที่ยังไม่บันทึกได้โดยไม่กระทบสื่อเดิม

หลังบ้าน → รายวิชา → บทเรียน → จัดการสื่อ → **เพิ่มสื่อในบทเรียนนี้** เลือกชนิดสื่อ ตั้งชื่อ แล้วบันทึก เพิ่มซ้ำได้ทั้ง 8 ชนิด รวมถึงสื่อชนิดเดียวกันหลายรายการ แต่ละรายการมีเนื้อหา ไฟล์/ลิงก์ สถานะแสดง/ซ่อน และลำดับของตัวเอง ผู้เรียนเห็นรายการทางซ้ายและเปิดดูทีละรายการ สื่อเดิมเป็นเนื้อหาหลักของบทเรียน ความก้าวหน้ายังนับเป็นรายบทเรียน

อัปเกรดจาก 1.9.x: รัน `database/migrations/1.10.0.sql` ผ่าน phpMyAdmin ก่อนใช้งานสื่อหลายรายการ ไม่ต้องนำเข้าฐานข้อมูลใหม่หรือย้ายสื่อเดิม หากยังไม่ได้รัน SQL บทเรียนเดิมยังใช้งานได้ ผู้ช่วย AI ยังคงใช้เฉพาะเนื้อหาบทเรียนหลัก

## โมดูล AI (เสริม) — ใช้ Claude ของ Anthropic

แยกการทำงานเป็น 2 ส่วน ปิด/เปิดได้ที่ **หลังบ้าน → ตั้งค่า AI** (ค่าเริ่มต้น: ปิด)

| ส่วน | ผู้ใช้ | ทำอะไรได้ | ที่อยู่ |
|---|---|---|---|
| **AI Teaching Assistant** | ครู / ผู้ดูแล | ร่างบทเรียน, สร้างแบบฝึกหัด, สร้างข้อสอบ (พร้อมเฉลย), สร้างเกณฑ์ Rubric, สรุปผลการเรียน, เสนอแนวทางปรับปรุงการสอน — จากเนื้อหารายวิชาที่เลือก | หลังบ้าน → รายวิชา → ปุ่ม ✨ / หน้าบทเรียน → "ผู้ช่วยสอน AI" (`admin/ai_teacher.php`) |
| **AI Learning Assistant** | ผู้เรียน | สรุปบทเรียน, อธิบายส่วนที่ยาก, คำใบ้ระหว่างทำแบบฝึกหัด (ไม่ให้คำตอบสำเร็จรูป), ถาม-ตอบ — จากเนื้อหารายวิชาที่ได้รับอนุญาตเท่านั้น | กล่อง "ผู้ช่วยการเรียนรู้ AI" ใต้เนื้อหาบทเรียน (`ai_learn.php`) |

**ครูต้องตรวจสอบก่อนเผยแพร่:** ทุกอย่างที่ AI สร้างเป็น "ฉบับร่าง" (`admin/ai_draft.php`) แก้ไขได้ด้วยตัวแก้ไข WYSIWYG
นำไปสร้างเป็นบทเรียนแบบซ่อนได้ทันที แต่การเผยแพร่ให้ผู้เรียนต้องติ๊กยืนยันว่าตรวจแล้ว (ข้อสอบ/แบบฝึกหัดต้องยืนยันว่าลบเฉลยแล้วด้วย)

**การควบคุม:** โควตาจำนวนครั้ง/คน/วัน (ครู/ผู้เรียน), ครูปิดผู้ช่วยของผู้เรียนรายวิชาได้ (เช่น ช่วงสอบ), สถิติการใช้งานและค่าใช้จ่ายโดยประมาณ 30 วัน,
เลือกโมเดลได้ (ค่าเริ่มต้น Claude Opus 5.5 / Sonnet 5.5 / Haiku 5.5), Opus/Sonnet เปิด server-side fallback เมื่อคำขอถูกปฏิเสธ

**ความเป็นส่วนตัว:** ไม่ส่งชื่อ/รหัส/อีเมลผู้เรียนให้ AI · สรุปผลการเรียนใช้สถิติไม่ระบุตัวตน · ไม่บันทึกข้อความคำถาม/คำตอบ (เก็บแค่จำนวน token ใน `ai_logs`)
· ประวัติสนทนาอยู่ใน session เท่านั้น · API key ไม่อยู่ในไฟล์สำรองข้อมูล · แม่แบบนโยบายความเป็นส่วนตัวมีหัวข้อผู้ช่วย AI แล้ว (แนะนำให้ประกาศนโยบายเวอร์ชันใหม่เมื่อเปิดใช้)

### ติดตั้ง (ต้องใช้ PHP 8.1+ และ Composer)

Anthropic PHP SDK ต้องใช้ PHP 8.1 ขึ้นไป — XAMPP เดิมของเครื่องนี้เป็น PHP 8.0 ต้องอัปเกรดก่อน:

1. **สำรองข้อมูล:** หลังบ้าน → สำรอง/กู้คืนข้อมูล → สร้างไฟล์สำรอง (รวมไฟล์อัปโหลด) → ดาวน์โหลด .zip เก็บไว้
2. ปิด Apache และ MySQL ใน XAMPP Control Panel แล้วเปลี่ยนชื่อโฟลเดอร์ `C:\xampp` เป็น `C:\xampp_old`
3. ดาวน์โหลดและติดตั้ง XAMPP เวอร์ชัน **PHP 8.2** จาก https://www.apachefriends.org ไปที่ `C:\xampp`
4. คัดลอกโฟลเดอร์ `C:\xampp_old\htdocs\lms` ไปไว้ที่ `C:\xampp\htdocs\lms` แล้วเปิด Apache + MySQL
5. เปิด http://localhost/phpmyadmin → สร้างฐานข้อมูล `vocational_lms` (Collation `utf8mb4_unicode_ci`) → แท็บ Import → เลือกไฟล์ `database.sql` (แตกจาก .zip ในข้อ 1)
6. ติดตั้ง Composer จาก https://getcomposer.org/download/ (Composer-Setup.exe — ตอนติดตั้งเลือก `C:\xampp\php\php.exe`)
7. เปิด Command Prompt แล้วรัน:
   ```
   cd C:\xampp\htdocs\lms
   composer install
   ```
8. สร้าง API key ที่ https://console.anthropic.com → API Keys (ต้องเติมเครดิตในบัญชี)
9. หลังบ้าน → ตั้งค่า AI → ใส่ API key → ติ๊กเปิดใช้งาน → บันทึก → กด **ทดสอบการเชื่อมต่อ**

หน้าตั้งค่า AI มีรายการ "ความพร้อมของระบบ" บอกว่ายังขาดขั้นตอนไหน · เว็บส่วนอื่นยังใช้งานได้ตามปกติแม้ยังไม่ได้ติดตั้งโมดูล AI

## PDPA (คุ้มครองข้อมูลส่วนบุคคล)

| เรื่อง | ที่อยู่ในระบบ |
|---|---|
| นโยบายความเป็นส่วนตัว | `privacy.php` (ลิงก์ท้ายทุกหน้า) — แก้ไขที่ หลังบ้าน → PDPA → นโยบายความเป็นส่วนตัว |
| ความยินยอม | ติ๊กยอมรับตอนสมัคร / ผู้ใช้เดิมถูกขอเมื่อเข้าสู่ระบบ (`consent.php`) / ประกาศเวอร์ชันใหม่ = ทุกคนยอมรับใหม่ |
| หลักฐานความยินยอม | ตาราง `consent_logs` (เวอร์ชันนโยบาย เวลา IP เบราว์เซอร์) — ดูที่ หลังบ้าน → PDPA → บันทึกความยินยอม |
| สิทธิขอเข้าถึง / โอนย้ายข้อมูล | ข้อมูลส่วนตัว → ดาวน์โหลดข้อมูลของฉัน (`my-data.php`, JSON) |
| สิทธิขอลบ / แก้ไข / คัดค้าน / ถอนความยินยอม | ข้อมูลส่วนตัว → ยื่นคำร้อง / ถอนความยินยอม → ผู้ดูแลจัดการที่ หลังบ้าน → PDPA (มีตัวนับ 30 วัน) |
| คุกกี้ | ใช้เฉพาะคุกกี้ session ที่จำเป็น + แถบแจ้งให้ทราบ |

> **ก่อนใช้งานจริง:** ใส่ชื่อสถานศึกษาและช่องทางติดต่อ DPO ที่ หลังบ้าน → PDPA → นโยบายความเป็นส่วนตัว
> และให้ DPO/ฝ่ายกฎหมายของสถานศึกษาตรวจทานเนื้อหานโยบาย (แม่แบบเริ่มต้นเป็นเพียงตัวอย่าง ไม่ใช่คำแนะนำทางกฎหมาย)

## สำรอง / กู้คืนข้อมูล

หลังบ้าน → **สำรอง/กู้คืนข้อมูล** (เฉพาะผู้ดูแลระบบ)

- **สำรอง:** ได้ไฟล์ `.zip` ที่มี `database.sql` (ทุกตาราง) + `uploads/` (ไฟล์สื่อ ภาพปก รูปโปรไฟล์) + `meta.json` เก็บใน `backups/`
- **กู้คืน:** เลือกจากรายการไฟล์บนเซิร์ฟเวอร์ หรืออัปโหลด `.zip`/`.sql` ต้องพิมพ์คำว่า "กู้คืน" เพื่อยืนยัน
  ระบบจะสำรองข้อมูลปัจจุบันเป็นไฟล์ `auto_...zip` ให้ก่อนทุกครั้ง ถ้ากู้คืนผิดไฟล์ ให้กู้คืนจากไฟล์ auto นั้น
- ไฟล์สำรองที่อัปโหลดต้องไม่เกิน `upload_max_filesize` (XAMPP = 40M) ถ้าใหญ่กว่านั้น ให้คัดลอกไฟล์ไปวางในโฟลเดอร์ `backups/` เอง แล้วกู้คืนจากรายการ
- โฟลเดอร์ `backups/` เปิดจากเว็บไม่ได้ แต่ควรดาวน์โหลดไฟล์สำรองเก็บไว้นอกเซิร์ฟเวอร์ด้วย

## สิทธิ์การใช้งาน

ผู้เรียนต้องเลือกกลุ่มเรียนจากรายการตอนสมัครสมาชิก กลุ่มดังกล่าวได้รับสิทธิ์เข้าเรียนเมื่อครูประจำรายวิชา (หรือผู้ดูแลระบบ) เลือกกลุ่มในหัวข้อ **อนุมัติกลุ่มเรียนเข้ารายวิชา** แล้วบันทึก กลุ่มหนึ่งได้รับสิทธิ์ได้หลายวิชา และสมาชิกใหม่ได้รับสิทธิ์ตามกลุ่มด้วย การอนุมัติบัญชีใหม่ยังขึ้นกับการตั้งค่าระบบ

รายวิชาใหม่ใช้ **เฉพาะกลุ่มที่ครูอนุมัติเข้าเรียน** เป็นค่าเริ่มต้น รายวิชาเดิมยังคงการตั้งค่าเดิม หากต้องการให้เข้าเรียนผ่านกลุ่มเท่านั้น ให้เปลี่ยนการลงทะเบียนในหน้าแก้ไขรายวิชา ผู้ดูแลจัดการได้ทุกกลุ่ม ครูสร้างกลุ่มและแก้ไข/ลบกลุ่มที่ตนเป็นผู้สอนได้ การลบกลุ่มไม่ลบบัญชีนักเรียน

- **ผู้ดูแลระบบ** — จัดการทุกอย่าง: สมาชิก ครู ตั้งค่า ทุกรายวิชาและทุกกลุ่ม
- **ครูผู้สอน** — สร้างรายวิชา, จัดการเฉพาะวิชาที่ตนสอน (บทเรียน ผู้เรียน กลุ่มที่ได้สิทธิ์), สร้าง/จัดการกลุ่มที่ตนเป็นครูผู้สอน
- **ผู้เรียน** — ลงทะเบียนวิชาแบบเปิด, เรียนวิชาที่กลุ่มของตนได้รับสิทธิ์, ติดตามความก้าวหน้า

## โครงสร้างไฟล์

```
config/      ตั้งค่าฐานข้อมูล (ห้ามเข้าถึงจากเว็บ)
database/    lms.sql (โครงสร้างตาราง), demo_data.php, migrations/ (SQL อัปเกรดเวอร์ชัน)
includes/    bootstrap, ฟังก์ชันช่วย, header/footer หน้าบ้าน
admin/       หลังบ้าน
assets/      CSS, รูปภาพเริ่มต้น
uploads/     ไฟล์ที่อัปโหลด (ปิดการรันสคริปต์ด้วย .htaccess)
backups/     ไฟล์สำรองข้อมูล (ห้ามเข้าถึงจากเว็บ)
vendor/      ไลบรารีจาก Composer (Anthropic PHP SDK) — สร้างด้วย composer install
```

## ความปลอดภัย

- รหัสผ่านเข้ารหัสด้วย `password_hash()`
- ทุก query ใช้ mysqli prepared statements
- ทุกฟอร์ม POST มี CSRF token
- อัปโหลดเฉพาะนามสกุลที่อนุญาต, เปลี่ยนชื่อไฟล์แบบสุ่ม, ปิด PHP ในโฟลเดอร์ `uploads/`
- เนื้อหา HTML ของบทเรียนผ่าน `clean_html()` ตัด script / event handler

ขนาดไฟล์อัปโหลดสูงสุดถูกจำกัดโดย `upload_max_filesize` / `post_max_size` ใน `php.ini` ด้วย (XAMPP ค่าเริ่มต้น 40M)


### แบบทดสอบปรนัย (1.12.0)

สำหรับระบบเดิม ให้รัน `database/migrations/1.10.0.sql` หากยังไม่มีตาราง lesson_media แล้วรัน `database/migrations/1.12.0.sql` (ไม่ต้องนำเข้า lms.sql ใหม่ เพราะจะล้างข้อมูลเดิม)

เลือก **แบบทดสอบปรนัย** ในหน้าแก้ไขบทเรียนหรือเพิ่มสื่อ กำหนดจำนวนข้อ 1–100 ข้อ กรอกโจทย์ ตัวเลือก 2–10 ตัวเลือกต่อข้อ และเลือกเฉลย จากนั้นบันทึก นักเรียนที่มีสิทธิ์เรียนส่งคำตอบแล้วจะเห็นคะแนนและประวัติของตนเอง ครูเปิด **ดูคะแนนแบบทดสอบ** ในหน้าแก้ไขบทเรียนเพื่อดูผลสอบทุกครั้ง ข้อละ 1 คะแนน และอนุญาตให้ทำซ้ำได้ คะแนนที่บันทึกไว้ไม่เปลี่ยนตามการแก้ไขข้อสอบภายหลัง การลบบทเรียนหรือบัญชีนักเรียนจะลบคะแนนที่เกี่ยวข้องด้วย


### ระบบส่งงานและตรวจงาน (1.13.0)

รัน `database/migrations/1.13.0.sql` หลังอัปเดต 1.12.0 แล้ว อัปโหลดไฟล์ `uploads/submissions/.htaccess` ให้ครบ (ระบบ Apache/XAMPP ต้องเปิด AllowOverride เพื่อบังคับสิทธิ์โฟลเดอร์นี้)

ครูเลือก **งานมอบหมาย / ส่งงาน** ในฟอร์มบทเรียนหรือสื่อเพิ่มเติม กำหนดคะแนนเต็มและคำสั่งงานในเนื้อหา นักเรียนที่ลงทะเบียนส่งข้อความ ลิงก์ผลงาน หรือไฟล์หนึ่งไฟล์ต่อครั้งได้ จากนั้นครูเปิด **ตรวจงาน** ในรายการบทเรียน หรือ **ตรวจงานและดูคะแนนการส่งงาน** ในหน้าแก้ไขบทเรียน เพื่อให้คะแนนพร้อมข้อเสนอแนะ หรือเลือกให้นักเรียนแก้ไขงาน

ทุกครั้งที่ส่งจะเป็นรายการใหม่ คะแนนเดิมไม่ถูกแทนที่ด้วยการส่งใหม่ คะแนนเต็มของรายการเดิมไม่เปลี่ยนตามการแก้ไขงานมอบหมาย นักเรียนดูประวัติของตนเองได้ในหน้างาน ครูดูรายการงานทั้งหมดได้ครั้งละ 25 รายการ ไฟล์ดาวน์โหลดผ่าน `assignment_file.php` ซึ่งตรวจเจ้าของงานและครูประจำรายวิชา ไฟล์งานรวมอยู่ในระบบสำรองข้อมูลแบบรวมไฟล์

### สมุดคะแนน ตัดเกรด และกำหนดเวลา (1.14.0)

รัน `database/migrations/1.14.0.sql` หลัง 1.13.0 แล้ว ครูเปิด **รายวิชา → บทเรียน → สมุดคะแนน / ตัดเกรด** เลือก **ดึงแบบทดสอบและงานมอบหมาย** จากนั้นเพิ่มรายการกรอกเอง เช่น คะแนนเข้าเรียน/กลางภาค/ปลายภาค กำหนดสัดส่วนรวม 100% (รายการไม่ใช้ให้ใส่ 0%) และเกณฑ์เกรด เกณฑ์เริ่มต้นคือ 80=4, 75=3.5, 70=3, 65=2.5, 60=2, 55=1.5, 50=1 และต่ำกว่า 50=0 มีปุ่มเกณฑ์ A–F และปรับทุกเกณฑ์เองได้

คะแนนแต่ละรายการคำนวณเป็นร้อยละของคะแนนเต็มครั้งนั้นคูณสัดส่วน คะแนนรวมปัดทศนิยม 2 ตำแหน่งก่อนเทียบเกรด ข้อสอบเริ่มต้นเลือกครั้งที่ได้ร้อยละสูงสุด งานเริ่มต้นเลือกฉบับล่าสุด เปลี่ยนวิธีเลือกได้ งานล่าสุดที่รอตรวจ/ให้แก้ไขต้องจัดการก่อนประกาศเกรด รายการไม่มีคะแนนนับศูนย์เฉพาะเมื่อครูเลือกยืนยัน รายการต้นทางถูกลบหรือเปลี่ยนชนิดต้องปรับสัดส่วนเป็น 0 ก่อนประกาศ

เลือกกลุ่มเรียนหรือรายบุคคล ดูตัวอย่าง กรอกคะแนนเองในหน้ารายบุคคล และส่งออก CSV ได้ ปุ่มบันทึกและประกาศผลทำงานกับผู้เรียนทั้งหมดในกลุ่มที่เลือก (ไม่ใช่เฉพาะคนที่กำลังดู) ผลเกรดเก็บเป็นรอบในประวัติ นักเรียนดูผลล่าสุดใน **ผลการเรียน** การแก้คะแนนต้นทางไม่เปลี่ยนผลที่ประกาศจนกว่าครูจะตรวจสอบและประกาศรอบใหม่

กำหนดวันเวลาในหน้าแก้ไขบทเรียนได้ที่ **วันเวลาเปิด–ปิดการสอน** ใช้กับสื่อทั้งหมดของบทเรียน ครูเปิดดูได้เสมอ งานมอบหมายแต่ละชิ้นมี **เริ่มรับงาน / กำหนดส่ง / รับงานหลังกำหนดส่ง** เว้นว่างเพื่อไม่จำกัดเวลา ใช้เขตเวลา Asia/Bangkok ปิดบทเรียนเมื่อถึงเวลาปิด รับงานตรงกำหนดส่งได้จนถึงเวลาที่ระบุ และหลังเวลานั้นติดสถานะส่งล่าช้าเมื่ออนุญาต หากบทเรียนปิด นักเรียนส่งงานไม่ได้แม้เปิดรับงานล่าช้า
